## TL;DR
Ido Salomon and Liad Yosef introduce MCP apps, an open protocol built on MCP that lets services send interactive, branded UI components directly into AI chat clients like Claude, ChatGPT, and VS Code. The speakers argue this transforms the web from browser-based tabs into an "agentic web" where personal assistants compose UI atoms from different brands, preserving brand identity while enabling rich, interactive experiences. The spec is evolving rapidly with community input, and the speakers encourage developers to get involved.

## Key Takeaways
- MCP apps solve the "text wall" problem: companies don't want their rich data and UX reduced to plain text in chat interfaces, and MCP apps let them send interactive, branded UI instead.
- The protocol standardizes bidirectional communication: apps can notify the host when users interact, and the host (not the app) decides what action to take, preserving user journey control.
- Major adopters include Claude, ChatGPT, VS Code, Cursor, GitHub Copilot, Postman, Shopify, 11 Labs, and PostHog, with OpenAI recommending MCP apps as the protocol for building ChatGPT apps.
- The architecture is simple: an MCP tool call links to a resource containing HTML, which the host renders in a sandbox via a React or web component, with callbacks handling interaction events.
- The "agentic web" vision: instead of opening 20 browser tabs to convey intent to separate services, a personal assistant composes UI chunks from trusted brands into a single contextual flow.
- MCP apps defines three levels of control over the user journey: apps can notify the host, request the host to run a prompt, or fully release responsibility to the host.
- The spec is under active development with features like reusable views (for heavy apps like Autodesk's 3D renderers), app tools/view tools (host-to-app communication), and a generative UI spectrum spanning predefined, declarative, and fully generative UI.
- Interoperability is a priority: a guide was recently released for bridging A2UI (Google's standard) with MCP apps, so a server can write once and ship to both Gemini and ChatGPT.
- The total addressable market is enormous — ChatGPT alone has 800 million weekly users (10% of the world population), roughly 170x the Apple App Store's TAM at launch.
- The working group meets tri-weekly under the MCP steering committee with Anthropic, OpenAI, and other partners; the community can contribute via the X apps repository.

### The Problem: Text as the Bottleneck [01:03](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=63s)
The speakers explain that text is the natural but worst interface for conveying rich information in chat clients. Companies hesitate to build MCP servers because they don't want to be "reduced to a textual database" and lose their brand identity. The core proposal: what if apps could send their own UI directly into the chat, preserving brand recognition (Shopify, Hugging Face, Monday.com) while remaining interactive?

### MCPUI Origins and Partnership with Anthropic/OpenAI [02:07](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=127s)
Ido created MCPUI in May of the previous year as an open protocol for interactive applications over MCP — covering not just UI transmission but also how that UI communicates with the host. A few months before the talk, they partnered with Anthropic and OpenAI to create the official MCP extension called MCP apps, based on MCPUI, the MCP SDK, and other solutions. Claude and VS Code were the first to support it, followed by OpenAI and others.

### Early Adopters and Current Client Support [03:10](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=190s)
Early adopters of MCPUI included 11 Labs, Shopify, Postman, and Goose. A notable anecdote: Goose was the first client to support MCPUI a year ago, and Block has now released their agentic commerce solution based on MCP apps. Current supporting clients include Cursor, GitHub Copilot, GitHub Chat, ChatGPT (whose apps are actually based on MCP apps), Postman, and Claude. A large community has formed around plugins, integrations, courses, and the X apps repository where anyone can propose PRs. A tri-weekly working group convenes under the MCP committee with Anthropic, OpenAI, and other partners.

### Core Concept: Transmitting UI Over MCP [05:12](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=312s)
Using existing MCP primitives, a server can return HTML via a resource. When the host (e.g., Claude) supports MCP apps, it renders that HTML as an interactive application. For interaction, MCP apps standardizes the flow: when a user clicks a button (e.g., "favorite" a song), the app sends a message to the host rather than directly to the backend. The host then decides whether to call a tool on the MCP server, maintaining control of the flow.

### Live Demo: PostHog Funnel in Claude [06:47](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=407s)
A product manager asks Claude about funnel status. In the old world, the PostHog MCP server would return a factually correct but useless wall of text. With MCP apps support on both the PostHog server and Claude host, saying "Show me" produces an interactive, branded PostHog widget. The user can ask Claude to explain what a funnel is and get a generative UI answer streamed as HTML. Clicking on a specific funnel step sends a prompt back to the model, advancing the agentic flow interactively.

### Architecture Deep Dive [08:52](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=532s)
The flow begins with a user prompt, triggering a tool call. If the server supports MCP apps, that tool call links to a resource (identified by a prefix) containing HTML. The host consumes that resource — sometimes preloaded — and renders the HTML in a sandbox using a React or web component from the MCP UI SDK, along with a callback implementing the communication protocol. When the user clicks, the event travels back through the callback to the model, which can then issue a tool call, resource request, or other action to complete the agentic flow.

### The Agentic Web Vision [10:26](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=626s)
The speakers articulate a paradigm shift: instead of consuming the web through browser tabs where users must manually convey intent to each service's dashboard, personal assistants will compose "atoms" of UI from trusted brands. Planning an anniversary no longer means opening Google Calendar, Amazon, Booking.com, etc. — the assistant pulls the relevant UI chunks (a Google Calendar chunk, an Amazon product view, a Booking.com map) into one contextual flow. This benefits users (familiar, trusted brands), brands (maintained identity), and hosts (no need to build capabilities themselves).

### New Interaction Model and Journey Control [12:32](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=752s)
With MCP apps, no single application controls the user journey — the host does. Amazon can't see the full flow; everything routes through the chat for auditability. MCP apps standardizes three levels of control: an app can notify the chat that something happened, ask the chat to run a prompt, or release all responsibility to the chat. The speakers predict 2026 will be the year MCP apps becomes a global standard for UI.

### Spec Evolution and Community Involvement [13:33](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=813s)
The spec is still evolving with many recent community contributions. The official SDK and spec are hosted in the X apps repository under the official model context protocol GitHub organization. Because the speakers maintain the SDK directly, all spec changes are immediately reflected in it. They encourage developers to contribute via open issues on the repo.

### What's Next: Reusable Views [14:35](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=875s)
A frequently requested feature is reusable views. Companies like Autodesk with heavy 3D rendering apps don't want to re-render entire views repeatedly. The team is exploring passing identifiers from the server so the model can keep updating the same view rather than recreating it each time — a limitation of the current MVP approach.

### App Tools and Host-to-App Communication [15:06](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=906s)
MCP apps standardizes bidirectional communication. While the initial flow covers user-to-app-to-host, the new "view tools" (app tools) feature covers host-to-app communication — for example, if a user says "fill out this form for me," the chat can populate the form inside the app. This is already in the spec and nearing release. The speakers reference Google's "web MCP" standard as a parallel they are aligning with.

### Generative UI Spectrum and Interoperability [15:36](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=936s)
The speakers describe a spectrum: predefined UI (MCP apps as a black-box iframe), declarative UI (JSON render or A2UI, where the server returns instructions and the chat builds the UI), and fully generative UI (like Claude's feature to generate a UI on demand, which is actually an MCP app behind the scenes). A guide was released days before the talk on interoperability between A2UI and MCP apps — a server can write A2UI for Gemini and wrap it as an MCP app for ChatGPT, or build an MCP app once and run it in both ChatGPT and LibreChat with the same codebase.

### Distribution and Market Opportunity [17:10](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=1030s)
The speakers frame MCP apps as an entirely new application distribution channel. ChatGPT has 800 million weekly users (10% of the world population) — a number that took the web 13 years to reach. Recent growth exceeded 1 billion, representing roughly 170x the total addressable market of the Apple App Store at launch. MCP apps are already supported across Claude, OpenAI, and other major platforms.

### Call to Action [18:13](https://www.youtube.com/watch?v=-jY2T2PiJBE&t=1093s)
The speakers encourage the audience to visit the official X apps repository, get involved as hosts or server builders, and "embrace the new web." They highlight the "write once, run everywhere" promise of MCP apps and invite attendees to talk with them after the session.
