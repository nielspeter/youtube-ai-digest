## TL;DR
Shreya Rajpal (Snowglobe) and Aman (Nubank) explain how Nubank uses simulation-generated evaluation data to ship AI customer support agents 20× faster, bypassing the bottleneck of manual data authoring and slow production A/B testing. By generating synthetic multi-turn conversations with mocked tools and personas, Nubank dramatically improved agent TNPS and self-service rate while validating that simulation data closely tracks real production data.

## Key Takeaways
- Evals consist of metrics and data; metrics have a working playbook (LLM-as-judge, alignment with human judgment), but data remains the true bottleneck—especially for multi-turn agents requiring stateful trajectories.
- Manual data authoring is extremely time-consuming; production traces are "almost free" but require testing on live users, making parallel experimentation difficult.
- Simulation short-circuits the release cycle from weeks to hours or minutes by generating thousands of synthetic multi-turn conversations on demand.
- Snowglobe wraps your agent with no code changes, mocks necessary tools, and drives simulations via personas and use cases, outputting datasets plus per-turn judge evaluations.
- Nubank verified in production that simulation data correlates highly with real data—80% of domain expert labels confirmed sims provide usable data for both mature and greenfield agents.
- Simulation caught regressions before production and identified issues that would have lowered self-service rate.
- One agent's TNPS doubled thanks to simulation-driven robust evals; self-service rate improved by 4% in one case without the typical TNPS/SSR trade-off.
- Simulation enabled rapid benchmarking of multiple open-source models against frontier models, saving weeks of effort.
- Closing the sim-to-real gap requires offline/online human review metrics to trust simulation results.
- Self-improving agent loops in enterprise settings ultimately come down to two fundamentals: aligned metrics and reliable data generation.

### Opening with Results [01:35](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=95s)
Aman shares production results: average TNPS (a customer satisfaction measure) for five AI agents has risen dramatically over a few quarters, with many agents now approaching or exceeding human quality. He references a KDD paper to be presented in Korea in August.

### Why Evals Are the Bottleneck [02:37](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=157s)
Shreya frames the talk in three parts: why evals matter but are a bottleneck, why simulated data works as well as collected data, and deep findings from implementing this at scale at Nubank. She explains that evals are about metrics and data—metrics have a playbook (LLM-as-judge classifiers aligned with human judgment, auto-optimization), but data generation remains the unsolved, expensive bottleneck, especially for agents where each data point is a multi-turn trajectory with stateful tool calls.

### The Cost of Manual and Production Data [04:40](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=280s)
Shreya contrasts the two main methods of obtaining eval data. Manual authoring is extremely time-consuming because you must hand-plan state updates and keep trajectories consistent across tool calls. Production traces are nearly free but require testing on live users, making large-scale parallel experimentation impractical. Aman adds that changing an agent harness takes hours, offline evals on hand-curated data take days, and production A/B tests with sparse, noisy customer feedback can take forever.

### How Simulation Short-Circuits the Timeline [06:12](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=372s)
Aman states that simulations compress the timeline from weeks to under a day—sometimes hours or minutes. Agent harness changes still take hours, but offline evals become fast because you have a simulated user to fall back on, and production-readiness checks that previously took weeks now take hours.

### What Mechanically Is a Simulation [07:30](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=450s)
Shreya explains Snowglobe's mechanics: point the SDK at your agent without code changes, identify tools to mock, and define personas, use cases, and data points to steer the simulation. Snowglobe outputs thousands of multi-turn conversations with mocked tools, then runs judges on top for per-turn behavioral evaluation that pipes directly into your eval pipeline.

### Example Simulation Output [08:46](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=526s)
Shreya walks through a concrete example: a synthetic persona named Maria Souza, a 34-year-old designer and first-time credit card customer, with consistent grounding data (fake address, credit card) and defined tone/voice. When run through the agent, the resulting conversation stays consistent with the simulated intent—the persona's curt one-line messages match her setup, and the agent receives valid mocked tool outputs.

### The Self-Improvement Loop [10:19](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=619s)
Aman describes Nubank's self-improvement loop: ship the agent, observe, create robust evals using automated prompt optimization (mentioning the "Japa" algorithm), run simulations, pipe sim and real data through evals for rich signal, optimize the agent harness, verify, and ship. This enables many A/B tests per agent across many agents company-wide.

### Sim-to-Real Correlation and Production Validation [11:22](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=682s)
Simulation quality via evals correlates highly with real data. Human review by domain experts confirmed that 80% of labels found sim data usable—not just for mature agents but also for greenfield agents built from scratch. Simulation caught a regression before it reached production and identified an issue that would have lowered self-service rate in another agent.

### Concrete Impact: TNPS and SSR [12:25](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=745s)
One agent's TNPS doubled. The team now runs many ideas through simulation and launches only one A/B test, short-circuiting the first five or six. Despite the common TNPS/SSR trade-off in customer service, Nubank improved SSR across the board—by 4% in one case—while keeping TNPS high.

### Benchmarking Open-Source Models [13:28](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=808s)
Aman highlights using simulation to rapidly test various open-source models in agent harnesses, throwing many model versions at the eval setup to see which perform best. This saved multiple weeks of effort, and A/B tests were actively running to compare open-source against frontier models.

### Three Core Takeaways [14:31](https://www.youtube.com/watch?v=KMR_RBoCa4M&t=871s)
Shreya summarizes: (1) Generate eval data in simulation rather than relying solely on production to short-circuit release bottlenecks. (2) Close the sim-to-real gap with offline/online human review metrics to trust simulation results. (3) Self-improving agents in enterprise come down to aligned metrics and reliable data generation—together they enable a continuous improvement loop.
