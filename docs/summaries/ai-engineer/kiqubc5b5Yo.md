## TL;DR
Brendan Rappazzo presents Morgan Stanley's AlphaLab, an agentic harness designed to automate quantitative research across financial prediction tasks. The system operates in three phases—research, eval building, and mass experimentation—using a multi-agent architecture with a strategist and worker agents. The talk covers the open-sourced AlphaLab 1.0, its initial results and failure cases, and the team's pivot toward building proprietary evals and environments as the key mechanism for encoding enterprise expertise and enabling self-recursive improvement in AlphaLab 2.0.

## Key Takeaways
- Morgan Stanley's ~30-person PhD AI research team operates half academically (publishing, open-sourcing) and half on applied internal work, with many problems resembling well-posed Kaggle-style prediction tasks.
- AlphaLab accepts a data path and natural-language prediction goal, then autonomously runs research, builds its own evaluation, and conducts mass experimentation to produce trained ML models.
- The harness is entirely custom-built (no off-the-shelf agent framework), giving maximum flexibility and provider agnosticism across OpenAI, Anthropic, and open-source models.
- Three core tools power the agents: full shell access, web search, and a Slurm-based GPU cluster abstraction for hardware orchestration.
- The experimentation phase uses a Jira/Kanban-style board where a strategist agent proposes experiments and worker agents implement, deploy, and analyze them, enabling self-evolution of strategy.
- AlphaLab 1.0 achieved decent results—top 12% on an Nvidia NeMo Kaggle competition and found meaningful improvements on internal models now entering production.
- The team encountered hard failures, prompting a major shift toward building strict, Kaggle-style evals and 10–20 carefully designed environments as reinforcement learning signals.
- A core thesis: general auto-research will become a commodity (already emerging with models like GLM 5.2), so enterprise value lies entirely in building proprietary environments and qualitative rubrics that encode domain expertise.
- AlphaLab 2.0 envisions a self-improving system where the LLM meta-optimizes the harness itself by examining traces and results, potentially orchestrating both open- and closed-source models.
- All code and a 40-page tech report for AlphaLab 1.0 are open-sourced on GitHub, with plans to continue releasing because the environments—not the harness—encode the proprietary value.

## Detailed Breakdown

### Team Context and Motivation [00:01](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=1s)
Rappazzo introduces his Morgan Stanley group of roughly 30 PhD AI researchers who blend academic publishing with applied internal work. Being on the sell side means less adversarial selection, making their prediction tasks naturally suited to automation. He identifies several motivations: squeezing more performance from existing production algorithms through additional compute cycles, transferring models across trading desks (e.g., credit bonds to muni bonds), and deploying ML to new desks where little AI automation currently exists. The effort became serious in December 2025 when models like Opus 4.5 and harnesses like Claude Code made long-horizon agentic tasks feel viable for the first time.

### Design Goals [03:07](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=187s)
The top-line objectives are maximizing P&L and increasing the number of production algorithms. Design concerns include integrating with existing data and backtesting infrastructure, supporting the full spectrum of use cases (from raw data with a natural-language goal to existing models needing more churn), remaining model-agnostic across frontier and open-source providers, ensuring the harness improves as models improve, and carefully encoding Morgan Stanley's enterprise knowledge and quant researcher expertise.

### AlphaLab 1.0 Overview [04:43](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=283s)
Released in early April with a 40-page tech report and fully open-sourced code on GitHub, AlphaLab 1.0 is an agentic harness that takes a data path or API spec plus a natural-language prediction target. It operates in three phases—research, eval building, and mass experimentation—outputting a suite of trained ML models. The harness is entirely custom code (Claude wrote much of it), avoiding off-the-shelf frameworks for maximum freedom and provider agnosticism via functional tool calling.

### Core Tools [07:18](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=438s)
Three main tools are available to the agents: full shell access for writing and running bash/Python code and managing environments; web search for reading arXiv and technical blogs to stay current on state-of-the-art methods; and a Slurm-based GPU cluster abstraction allowing the model to request hardware (e.g., 4 H100s) and submit jobs without manual orchestration.

### Phase 1: Research [08:19](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=499s)
The research phase functions like a "super CLAUDE.md" or "super init," building enough context for meaningful hypothesis formation. A lightweight UI scaffolds a to-do list—if every item were completed, the system could begin experimenting. Each item generates notes in a markdown file, enabling feature agents to manage context dynamically. This phase, which heavily uses web search, takes roughly 3–4 hours.

### Phase 2: Eval Building [09:52](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=592s)
Recognizing that LLMs can make silly mistakes and optimizing against a bad eval collapses the whole effort, the team uses a multi-agent framework: one agent builds the eval code, then two critic agents review it—one checking for conceptual errors and forward-looking data leakage, the other writing unit and integration tests. Issues loop back to the builder until all agents are satisfied. Rappazzo notes this phase is the most changed element in AlphaLab 2.0.

### Phase 3: Mass Experimentation [10:53](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=653s)
The heart of the system, visualized as a Jira/Kanban board. A strategist agent queries context from prior steps and continuously proposes experiments. Worker agents implement the code, write Slurm configs, submit jobs, analyze training curves for overfitting/underfitting, and write postmortem analyses that feed back to the strategist for self-evolution. Users can steer the process by canceling cards, adding their own, or chatting with the strategist. An ever-growing leaderboard tracks the best-performing models on both public and held-out private validation sets.

### Initial Results [13:26](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=806s)
AlphaLab was benchmarked on academic datasets (CUDA kernels, traffic time series, Karpathy-style LM speedrunning), where it found a better LLM training config than a single-agent-in-a-loop baseline. On an Nvidia-hosted Kaggle competition to fine-tune NeMo Tron as a reasoning model, it placed in the top 12% despite only having ~10 iterations due to a late entry. Internally, it found meaningful improvements on existing models that are now working through risk review toward production.

### Failure Cases and Hard Questions [14:30](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=870s)
Despite successes, AlphaLab failed on hard problems, raising questions about how real the results are. Rappazzo also questions whether the strategist/worker architecture is arbitrary and whether design choices should be made by humans at all. A third concern: the 1.0 formulation gives data and a goal to the LLM but doesn't explicitly encode Morgan Stanley's enterprise knowledge or quant expertise. The answer to all three, he says, lies in building proprietary evals and environments.

### The Pivot to Environments and Evals [15:32](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=932s)
The team became "very opinionated about the eval," adopting a strict Kaggle-style format: data and description in, containerized models out, with public leaderboard feedback for the harness and private held-out validation for users. They built 10–20 careful environments that serve as reinforcement learning signals. This enables both human tuning of the harness (e.g., testing whether two debating strategists perform better) and automated meta-harness optimization where the LLM examines traces and results to improve the harness itself. They are also collecting good traces from open-source models for on-policy distillation methods like GRPO, envisioning an orchestration of open- and closed-source models optimized together.

### Encoding Expertise Through Rubrics [18:08](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=1088s)
Building good environments is hard work. Beyond proprietary data and verifiable metrics, the team designs qualitative rubrics that grade traces on how well they follow Morgan Stanley's research process—capturing what makes a good researcher's thought process. These rubrics become the learning signal, embedding human expertise into the system.

### AlphaLab 2.0 Vision and Conclusion [18:39](https://www.youtube.com/watch?v=kiqubc5b5Yo&t=1119s)
AlphaLab 2.0 centers on the strict environment/eval setup; whatever lives in the middle can be initialized to 1.0 but should become a self-improving system. Rappazzo's headline thesis: general auto-research will become a commodity (already visible with GLM 5.2), so all enterprise and human expert value lies in building environments. The team plans to keep open-sourcing their work because the environments—not the harness—encode the proprietary value.
