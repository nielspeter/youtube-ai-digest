# Why AI Agents Need a Data Harness, Not Just a Lakehouse

[![Why AI Agents Need a Data Harness, Not Just a Lakehouse](https://i.ytimg.com/vi/xR-BiPz45-4/hqdefault.jpg)](https://www.youtube.com/watch?v=xR-BiPz45-4)

## TL;DR
Will Martin, Data and AI Evangelist at Dremio, argues that AI agents require a "data harness" — a performant, open-standards-based data foundation — rather than just a traditional data lakehouse. He explains how combining an open catalog, a semantic layer, and a fast query engine provides the sub-second, conversational pace and reliable context that agentic analytics demands.

## Key Takeaways
- **Agents need conversational pace:** Legacy analytics that take minutes or hours are unacceptable for AI agents; they require sub-second responses to avoid pipeline errors and wasted tokens.
- **Three pillars of a data harness:** A performant data harness consists of an open catalog, an AI semantic layer, and a fast query engine.
- **The semantic layer is critical:** Because business terms (like "revenue" or "customer") are subjective and vary by company, a semantic layer is necessary to provide AI agents with a single source of truth.
- **Open standards prevent lock-in:** Using open-source projects like Apache Iceberg, Apache Arrow, and Apache Polaris allows organizations to build performant data platforms without being tied to a single vendor.
- **Performance requires optimization:** Features like data compaction, vacuuming, variant shredding, and intelligent caching (like Dremio's Reflections) are essential to speed up query performance.
- **Governance applies to agents:** AI agents access data through user accounts, meaning existing role-based access controls (RBAC) and fine-grained access controls automatically apply to what the agent can see and do.
- **Federation over centralization:** Instead of physically moving all data into a warehouse, data federation allows you to query data where it lives, centralizing access and governance without the pain of centralization.

Martin explains Dremio's position as a lakehouse provider and highlights their heavy investment in open source standards. ### What is a Data Lakehouse? [03:44](https://www.youtube.com/watch?v=xR-BiPz45-4&t=224s)
A lakehouse combines the low-cost, scalable storage of a data lake with the reliable ACID transactions of a data warehouse. It requires two main components: a metadata catalog (to provide the right version of data) and a table format (metadata about the data, like schema and history).

### The Need for Speed in Agentic Analytics [06:23](https://www.youtube.com/watch?v=xR-BiPz45-4&t=383s)
Martin shifts to the core topic: why traditional data infrastructure falls short for AI. Legacy analytics operated at an "email pace" where queries taking minutes or hours were acceptable. However, agentic analytics operates at a "conversation pace." If an agent takes ten minutes to respond, it's a poor experience, pipelines may error out, and tokens are wasted. Agents require sub-second responses.

### The Three Components of a Data Harness [09:01](https://www.youtube.com/watch?v=xR-BiPz45-4&t=541s)
To support AI, a data foundation must be accessible, understandable, and performant. Martin introduces the three components of Dremio's performance data harness: the open catalog, the AI semantic layer, and the query engine.

### The Open Catalog and Optimization [11:08](https://www.youtube.com/watch?v=xR-BiPz45-4&t=668s)
The Dremio Open Catalog is powered by Apache Polaris. It includes features like Iceberg clustering (an alternative to partitioning), table maintenance (garbage collection and compaction to solve the "small file problem"), and variant shredding (for efficiently querying semi-structured data in a cell). It also provides end-to-end access control, from storage-level credential vending to row and column-level masking.

### The AI Semantic Layer [14:52](https://www.youtube.com/watch?v=xR-BiPz45-4&t=892s)
Martin explains that business terms are subjective and vary not just between companies, but within them (e.g., how "sales" or "customer" is defined). If these definitions are kept in separate tools or spreadsheets, AI will guess—often incorrectly. The semantic layer consolidates this context into the platform, allowing agents to reliably find metric definitions, understand table relationships, and explain what the data means.

### The Query Engine and Federation [19:08](https://www.youtube.com/watch?v=xR-BiPz45-4&t=1148s)
The query engine handles data federation, allowing users to query data where it lives rather than physically centralizing it. Martin discusses caching features, including query plan caching, results set caching, and Columnar Cloud Cache (C3), which places frequently accessed data next to compute nodes. He also mentions Reflections, a custom query acceleration feature.

### The Open Data Harness and Interoperability [21:17](https://www.youtube.com/watch?v=xR-BiPz45-4&t=1277s)
Because Dremio uses open standards like Apache Iceberg and the Iceberg REST spec, organizations are not locked into one vendor. Different query engines (like Snowflake, Athena, or Trino) can communicate with different catalogs out of the box. This allows organizations to build a data platform based on performance, cost, or preference.

### Q&A: Token Waste and Agent Guardrails [25:03](https://www.youtube.com/watch?v=xR-BiPz45-4&t=1503s)
An audience member asks how to prevent an AI from wasting tokens by calculating something from scratch instead of using a pre-formatted version. Martin explains that guardrails are largely the responsibility of the builder using tools like MCP, though Dremio provides discrete actions and tracks spend for its built-in UI agent.

### Q&A: Exposing Functionality to Agents [27:08](https://www.youtube.com/watch?v=xR-BiPz45-4&t=1628s)
When asked how to expose data functionality to agents for tasks like composing data products, Martin clarifies that agents access the platform through the semantic layer and MCP endpoints. For more complex, multi-agent workflows, he recommends using the CLI approach, which provides structured JSON feedback and is more cost-effective.

### Q&A: Access Control for Agents [31:14](https://www.youtube.com/watch?v=xR-BiPz45-4&t=1874s)
Martin confirms that access control machinery applies to agents. Agents access data through a user account, meaning they are subject to the same role-based and fine-grained access controls as the human user they are acting on behalf of. He notes that Dremio works with Genomics England, where this type of access control is critical.

### Q&A: Open Semantic Interchange (OSI) [32:59](https://www.youtube.com/watch?v=xR-BiPz45-4&t=1979s)
An audience member asks about the relationship between OSI and semantic web technologies. Martin compares OSI to Apache Arrow, noting that while Arrow standardized in-memory processing and transport, OSI is currently focused on a standardized format (primarily JSON) for sharing semantic information between systems to avoid vendor lock-in of business context.

### Q&A: Agent Awareness of Query Latency [34:37](https://www.youtube.com/watch?v=xR-BiPz45-4&t=2077s)
When asked if agents can be made aware of query latency to optimize their calls, Martin explains that Dremio's approach is to handle performance on the backend. Instead of making the agent aware, Dremio uses Reflections—automatically creating materialized tables to speed up slow queries without the user or agent needing to change their SQL.
