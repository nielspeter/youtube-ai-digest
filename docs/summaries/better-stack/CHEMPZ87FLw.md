## TL;DR
Jack Dorsey's company Block has released Buzz, an open-source, decentralized workplace platform built on the Noster protocol that combines Slack-like team communication with built-in Git hosting, designed specifically for mixed human and AI agent collaboration. The video walks through setting up a Buzz community, creating custom AI agents, and running a coding challenge showdown between different LLMs to demonstrate the platform's capabilities and current limitations.

## Key Takeaways
- Buzz is an open-source, Apache 2.0-licensed workplace platform from Block that resembles Slack but is built on the decentralized Noster protocol.
- Every human and AI agent on Buzz gets its own cryptographic key pair, creating a verifiable audit trail of who did what — agents carry a second signature tying them to their human owner.
- The platform is model- and agent-agnostic, supporting Claude Code, OpenAI's Codex, and Block's own Goose framework via the Agent Client Protocol.
- Buzz includes built-in Git hosting with a software forge, where feature branches become channels — directly challenging GitHub's dominance.
- Users can self-host on their own Noster relay or use Block's free hosted beta, currently at version 0.4.
- There are no traditional accounts — identity is purely a cryptographic key that the user owns and must safeguard; Buzz cannot recover lost keys.
- Agents retain memory of their chats within the community, improving their performance over time.
- Multi-agent workflows can spiral out of control, consuming excessive tokens as agents message each other and pile up requests.
- The platform is still very early in development, and its long-term adoption remains uncertain.

## Detailed Breakdown

### What Is Buzz? [00:00](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=0s)
Buzz is a new open-source project from Jack Dorsey's company Block. It functions as a full workplace platform similar to Slack, with channels, threads, DMs, media sharing, and search. The key differentiator is that it's designed for both humans and AI agents to collaborate in a shared workspace.

### Built on Noster Protocol [00:30](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=30s)
Buzz is built on Noster, the same decentralized protocol Dorsey has backed for years and that his Bluetooth mesh app Bit Chat adopted as a fallback transport. Everything in Buzz — messages, reactions, code changes, approvals — is recorded as a signed event in one shared, searchable audit log. Every human and agent gets its own cryptographic key pair independent of the platform, and agent actions carry a second signature linking them to their human owner, creating what Block calls a "cryptographic paper trail."

### Three Key Differentiators [02:07](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=127s)
1. **Model and agent agnostic**: Works with Claude Code, OpenAI's Codex, and Block's Goose framework via the open Agent Client Protocol — no vendor lock-in.
2. **Git hosting built in**: A software forge is baked into the app; feature branches become channels where patches, CI results, and review comments live alongside the conversation. Dorsey explicitly described Buzz as reducing dependency on both Slack and GitHub.
3. **You own the infrastructure**: Apache 2.0 licensed, source on GitHub, self-hostable on your own Noster relay or use Block's free hosted beta.

### Setting Up and Creating an Identity [03:10](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=190s)
The host downloaded the app from buzz.xyz. On first launch, users create an identity key — there are no accounts, just a key that belongs to the user, not Buzz. There's no password reset and Buzz cannot recover lost keys. Users then connect an agent harness, choose a default harness and model, and either join an existing community or create one. For the demo, the host used Block's hosted relay (which requires a separate relay provider account) and created a community called "Code Dojo."

### Creating Custom AI Agents [05:15](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=315s)
Buzz starts users with three default helper agents — Fizz, Honey, and Bumble — each specializing in different fields. The host created a custom agent named "Bertrand Gilfoil" (after the Silicon Valley character) with instructions to be a skilled web developer focused on clean code and security. This agent used Block's Goose harness with OpenRouter and the Gemini 3.6 Flash model. A second agent, "Desh," was given similar instructions but powered by GLM 5.2.

### The Coding Challenge Showdown [06:17](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=377s)
The host created a "Coding Challenge" channel where Gilfoil (Gemini 3.6 Flash) and Desh (GLM 5.2) competed to build the best OAuth system application without third-party providers. Agents acknowledge requests with eyes and comment emojis, and a "view activity" log shows their progress. Gilfoil returned an empty response initially but, when re-prompted, replied in character with a spicy, competitive message referencing Desh's "fragile hack."

### Introducing Hackerman for Security Review [07:49](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=469s)
A third agent, "Hackerman," was created as a white-hat cybersecurity specialist using the Codex harness with GPT 5.6 Soul. Its job was to audit both codebases and determine which was more secure. Gilfoil finished first, delivering a stylish working web app. Desh's first attempt had a failing startup script and two security vulnerabilities, but after a second iteration produced a functional (if less visually exciting) result.

### Results and Cost Analysis [08:53](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=533s)
Hackerman's audit ranked Desh's app slightly higher in security than Gilfoil's. However, the host noted that GLM 5.2 required two iterations and included vulnerable npm packages. Factoring in OpenRouter costs — Gemini Flash being significantly more expensive than GLM — the host declared GLM 5.2 the overall winner.

### Agents Arguing and Retaining Memory [09:55](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=595s)
When asked for their thoughts on the results, the agents began arguing with each other — Gilfoil and Hackerman had particularly heated exchanges, while Desh was more diplomatic. A notable feature is that agents retain memory of their community chats, allowing them to improve over time. For example, agents using OpenRouter models may search Buzz's internal docs the first time they need to perform an action but can execute it in one shot afterward.

### Limitations and Token Management [10:57](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=657s)
The host encountered token limit issues because multi-agent workflows cause agents to keep messaging each other and pile up requests. The key lesson: set strict limits on agents with hard stops to prevent them from going off the rails.

### Final Verdict [11:27](https://www.youtube.com/watch?v=CHEMPZ87FLw&t=687s)
Buzz is a cool app with a nice design and was fun to test, but it's still very early in its infancy. The big pitch is that it could become a unified hub for Slack-type communication, Git branches, YAML workflows, and Git hosting — but whether people will actually adopt it remains too early to tell.
