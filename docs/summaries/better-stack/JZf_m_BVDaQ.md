## TL;DR
Canvas UI is an open-source, framework-agnostic component library of 33 tasteful HTML and WebGL effects, installable via the Shadcn CLI so you own the code. It showcases cutting-edge "HTML in Canvas" effects—experimental browser capabilities that apply GPU/shader-like effects to live DOM elements—and also has practical, ship-today use cases like code-driven video effects.

## Key Takeaways
- Canvas UI is an open-source, framework-agnostic component library currently featuring 33 components.
- Components are installed via the Shadcn CLI, meaning the code is added directly to your codebase and you own it; dependencies like Three.js are installed automatically.
- The library is split into two categories: WebGL/Three.js effects (which work on most modern browsers) and "HTML in Canvas" effects (which require an experimental Chrome feature flag).
- A major strength of the library is its graceful fallbacks—on unsupported browsers like Firefox, effects simply render as normal web pages without breaking.
- "HTML in Canvas" is a WICG proposal that introduces methods like `drawElementImage`, allowing real, live DOM elements to be drawn into a canvas or used as textures in WebGL/WebGPU while remaining in the accessibility tree.
- This approach solves the trade-offs of previous GPU-over-content methods, which either required rebuilding content inside a canvas (breaking accessibility/search) or screenshotting the DOM (incomplete CSS support).
- The presenter highlights five favorite components: Decrypt Reveal, Flame Wrap, Pill, Ripple, and Shatter.
- A practical, niche use case for the library today is applying its effects to code-generated videos using tools like Remotion and Hyperframes.
- The presenter would happily ship the WebGL overlay effects on marketing sites today, but would reserve the HTML in Canvas effects for demo sites and video editing for now.

### WebGL vs. HTML in Canvas Effects [01:02](https://www.youtube.com/watch?v=JZf_m_BVDaQ&t=62s)
The library is split into two types of components. The first uses WebGL and Three.js, which works on most modern browsers. The second uses HTML and Canvas, an experimental browser capability requiring a Chrome feature flag. An example of the latter is the "bend" effect, where HTML curves around the page as you scroll.

### Graceful Fallbacks for Unsupported Browsers [01:32](https://www.youtube.com/watch?v=JZf_m_BVDaQ&t=92s)
A key feature of the library is that effects don't break on incompatible browsers. When switching to Firefox (which lacks the feature flag), the "bend" component simply renders as a normal web page. Similarly, the "blaze" effect works in Firefox but looks much cooler in Chrome with the feature flag enabled, showing a heat distortion effect. The "bubble" effect also demonstrates this, showing a liquid glass distortion in Chrome but a normal bubble in Firefox.

### What is HTML in Canvas? [02:33](https://www.youtube.com/watch?v=JZf_m_BVDaQ&t=153s)
The presenter explains that HTML in Canvas is a WICG proposal that adds a method called `drawElementImage`, which takes a real DOM element and draws it inside a canvas. It also includes `textElementImage2D` for WebGL and `copyElementImageToTexture` for WebGPU. The key is that the HTML element stays a real element—remaining in the accessibility tree, staying selectable, and updating the canvas when it updates. It solves the trade-offs of previous methods (rebuilding content in canvas or screenshotting the DOM), essentially acting as "shaders for HTML" or a reincarnation of Flash.

5. **Shatter [06:09](https://www.youtube.com/watch?v=JZf_m_BVDaQ&t=369s):** Shatters the underlying HTML into 3D glass shards as the mouse moves. Another great showcase of HTML in Canvas for marketing sites.
