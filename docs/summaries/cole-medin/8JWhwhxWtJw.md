# The Ultimate Knowledge Base: Bring YouTube Into Your AI Second Brain

[![The Ultimate Knowledge Base: Bring YouTube Into Your AI Second Brain](https://i.ytimg.com/vi/8JWhwhxWtJw/hqdefault.jpg)](https://www.youtube.com/watch?v=8JWhwhxWtJw)

## TL;DR
Cole Medin demonstrates how to build an AI-queryable knowledge base from an entire YouTube channel using Google's Open Knowledge Format (OKF), packaging all 200 of his own videos into a shareable bundle that agents can search and cite with timestamps. He walks through the structure of the knowledge base, the canonicalization pipeline that extracts concepts and entities from raw transcripts, and provides reusable skills so viewers can replicate the process for any YouTube channel.

## Key Takeaways
- **Open Knowledge Format (OKF)** is Google's new open standard for creating agent-readable knowledge bases, analogous to what MCP did for agent-to-tool and A2A did for agent-to-agent communication.
- The entire knowledge base is built from **markdown transcripts** of YouTube videos, making it easy for both humans and agents to navigate.
- An **index file** serves as the entry point for the agent, providing themes and a high-level overview of what questions the knowledge base can answer.
- **Canonicalization** is the most complex step—identifying recurring concepts and entities across videos, fuzzy-matching variant names (e.g., "PIV loop" vs. "plan implement validate workflow"), and aggregating them into dedicated files.
- Only concepts and entities mentioned **more than once** get their own files; one-off mentions are excluded to keep the knowledge base scalable.
- The **graph view in Obsidian** automatically visualizes how concepts, entities, and videos interconnect through document cross-references.
- Getting started with Cole's prebuilt knowledge base requires **a single prompt** sent to an agent like Claude Code, which clones the repo and is immediately ready for questions.
- Three **skills** are provided for building your own knowledge base from any channel, differing only in the transcript-fetching service used (Super Data API, YouTube Transcript API, or YT-DLP).
- The process is **token-heavy** due to the volume of LLM reasoning required, but the payoff is a deeply interconnected, queryable second brain.

Users copy a single prompt from the README, send it to their agent (e.g., Claude Code, Hermes, or Open Claude), and the agent learns OKF if needed, clones the knowledge base, and is immediately ready for questions.

### Structure of the OKF Knowledge Base [03:36](https://www.youtube.com/watch?v=8JWhwhxWtJw&t=216s)
Cole walks through the file structure: a README for humans, an index file as the agent's entry point, and themes that give the agent a high-level overview of the knowledge contained. Everything is markdown—raw transcripts plus extracted concept and entity files. He shows how to browse the files in VS Code or Obsidian, and highlights Obsidian's graph view, which visualizes the dense web of connections between concepts like "context engineering," "vibe coding," "validation," and the "sub-agent pattern."

### SerpApi Sponsorship Segment [06:09](https://www.youtube.com/watch?v=8JWhwhxWtJw&t=369s)
Cole introduces SerpApi, a web search API that returns structured JSON from live Google, YouTube, Bing, and other search engines without the need for scrapers, proxies, or captcha-solving. He notes its model-agnostic design, real-time results, and additional APIs for Google Scholars, Google Images, news, trends, and maps. Viewers can get 250 free credits via a link or QR code.

### Building the Knowledge Base: Transcript Extraction [07:41](https://www.youtube.com/watch?v=8JWhwhxWtJw&t=461s)
The first pipeline step is extracting YouTube transcripts as markdown documents, stored in a "raw" folder. Each file contains the full timestamped transcript of a video. These raw transcripts serve as the ultimate source for citations and exact timestamps when the agent answers questions.

### Canonicalization: Extracting Concepts and Entities [08:43](https://www.youtube.com/watch?v=8JWhwhxWtJw&t=523s)
The most complex step is canonicalization—taking a bird's-eye view of all transcripts to identify recurring entities (e.g., tools like "BMad Method," "Bolt.new," "AGUI") and concepts (e.g., "abstraction distraction"), then aggregating information about each into dedicated files. Cross-references between documents automatically build the Obsidian graph view. Cole explains the challenge of fuzzy-matching variant names for the same concept, such as "PIV loop," "plan implement validate workflow," and "plan build verify," which the LLM must reason about to unify. One-off mentions are excluded to keep the knowledge base scalable.

### Skills for Building Your Own Knowledge Base [11:50](https://www.youtube.com/watch?v=8JWhwhxWtJw&t=710s)
Cole provides three skills in the repo, each using a different transcript-fetching service: Super Data API (paid, most reliable), YouTube Transcript API, and YT-DLP (both free). He notes the YouTube Data API can't pull transcripts for channels other than your own, necessitating third-party tools. Each skill includes a script to fetch transcripts and a `skill.md` file with instructions that guide the agent through reading the OKF spec, pulling transcripts, canonicalizing, and writing entity and concept files. To run it, users invoke `/channel2kb` in Claude Code with a channel URL or handle like `@ColeMedin`.
