# My Super Simple Software Factory (For Agentic Engineers)

## TL;DR
IndyDevDan presents his open-source "Super Simple Software Factory" (SSSF), a system for building reproducible AI developer workflows (ADWs) that combine agents, deterministic code, and engineer oversight. The core thesis is that agents plus code beats agents alone, and software factories give you leverage on your prompts by making agentic work observable, customizable, and reusable across hundreds or thousands of runs.

## Key Takeaways
- **Software factories = leverage on your prompt.** The more you invest in the factory's workflows, the more leverage you get—scaling from simple chained agents to fully autonomous systems.
- **Agents + code beats agents alone.** Deterministic code should handle validation, tests, and formatting; agents should only be invoked when non-deterministic reasoning is required. Passing passing tests back into an agent's context window is wasteful.
- **Three design principles:** The SSSF is observable, customizable, and reusable.
- **The "core four" of agent configuration:** Context, model, prompt, and tools. Mastering these four for each agent is the key to specialization.
- **Model stack over model loyalty.** The best engineers no longer debate which single model is best; they use a stack of models (state-of-the-art, workhorse, lightweight) at the right cost and speed for each specific task.
- **Determinism is wired into every step.** Agents must output specific JSON types and structures that get validated. If validation fails, the agent must re-output correctly.
- **Agentic access is a key pillar.** The system is designed to be operated by agents at agentic speed, not manually by humans—unless you're building the system that builds the system.
- **Think about the thousandth run, not the first.** The factory is built for reliability and consistency over hundreds or thousands of executions without you.
- **Vibe coding vs. agentic engineering.** Vibe coding is not knowing how your system works; agentic engineering is knowing how it works so well you don't have to look.

Dan opens by distinguishing his audience: engineers building systems of agents, not those "mindlessly vibe coding slop." He defines a software factory as a misunderstood but powerful tool that gives you more leverage on your prompt. The leverage scales with investment—from chaining a few agents to building a fully autonomous system of agents plus code.

### Three Design Principles & Observability [01:33](https://www.youtube.com/watch?v=haUfb1ievTE&t=93s)
The Super Simple Software Factory (SSSF) is built on three principles: observable, customizable, and reusable. Dan demonstrates observability by showing a swim-lane view of an AI developer workflow (ADW) where multiple models (Kimmy K3, Gemini 3.6 Flash, GPT 5.6) run in parallel. He emphasizes that the best engineers no longer debate which single model is best; they use software factories to scale compute and impact across a stack of models.

### The Three Actors of Value Creation [02:35](https://www.youtube.com/watch?v=haUfb1ievTE&t=155s)
Dan defines the three actors: the engineer, the code that executes, and the agent. The factory isn't just about running agents in parallel; it's about combining all three at the right time. He shows how you can dial into any agent phase to inspect compiled system and user prompts, agent configs, tools, and the specific agent harness—enabling sub-engineering disciplines like prompt, context, and harness engineering.

### Agentic Access & Running a Simple Workflow [03:37](https://www.youtube.com/watch?v=haUfb1ievTE&t=217s)
Using the Herder terminal multiplexer (having transitioned from tmux), Dan fires up a Pi coding agent running Opus 5. A key feature of the SSSF is "agentic access"—the ability to move at agentic speed by having an agent orchestrate the system rather than operating it manually. He runs a simple two-phase "scout" workflow on a test app called Inkwell, using the cost-effective Gemini 3.6 Flash model, and reviews the agent's proposed features.

### Intermediate Workflow: Plan, Build, Test [06:45](https://www.youtube.com/watch?v=haUfb1ievTE&t=405s)
Dan escalates to a three-step ADW: plan, build, test. He tasks the system with adding a light mode to the Inkwell app. The planner uses Kimmy K3 (run via Fireworks serverless endpoints), and the builder uses Gemini 3 Flash. Dan notes that Kimmy K3 is the first open-weights model in the state-of-the-art tier, though it "thinks a lot" and isn't as fast as Opus. He praises Fireworks for addressing AI model ownership and cheap serverless inference without appropriating user data.

### Code as a First-Class Citizen [09:20](https://www.youtube.com/watch?v=haUfb1ievTE&t=560s)
After successfully adding light mode, Dan stresses a major idea: not everything needs to be agentic. He pushes back against the "agent-pilled" AI psychosis that ignores the fact that code is essentially free, runs at the speed of light, and—crucially—is owned by you, unlike rented AI models. He treats code as a first-class citizen in the factory, using deterministic gate checks after the plan step. Agents output structured JSON that is validated; if it fails, the agent must correct it.

### The Full SDLC Workflow [14:29](https://www.youtube.com/watch?v=haUfb1ievTE&t=869s)
Dan runs the full Software Developer Life Cycle (SDLC) workflow to add a side-by-side markdown viewer to Inkwell. He uses a "state-of-the-art configuration," setting Claude Opus 5 as the planner. He compares Opus 5 to Fable 5, noting that while benchmarks favor Opus 5, his experience still puts Fable 5 slightly above, though Opus 5's price makes it the model of choice. The workflow includes plan, build, test, review, and documentation phases.

### Inside the Codebase [16:33](https://www.youtube.com/watch?v=haUfb1ievTE&t=993s)
Dan opens VS Code to show the SSSF is wrapped in a single skill. The ADWs are Python files using `with` statements to denote phase entry and exit. He shows a 180-line simple SDLC file, clearly separating agent calls from deterministic code checks (e.g., `kind=engineer`, `kind=agents`, `kind=code`). He emphasizes staying in distribution—using just Python, YAML, and standard agent tools rather than inventing a new DSL.

### The Core Four & Agent Configuration [18:07](https://www.youtube.com/watch?v=haUfb1ievTE&t=1087s)
The system reads simple YAML config files to define each agent's "core four": context, model, prompt, and tools. Dan shows the planner config (Kimmy K3 via Fireworks, thinking high) and the builder config, noting that each agent can have a unique, specialized agent harness. For example, he added sub-agent support to the planner so it can spin up its own sub-agents if needed.

### Reviewing the Full Workflow Results [21:13](https://www.youtube.com/watch?v=haUfb1ievTE&t=1273s)
The SDLC workflow completes successfully. Dan shows the high-level view: full model customization, cost analysis, and phased work (plan, build, review). He highlights the review step, where an agent asks "is what we built what we asked for?" He explains the diff step, which documents work done for the next engineer or set of agents. He stresses thinking about the thousandth run, not the first, to build systems that win repeatedly.

### Extensibility & Reusability [24:49](https://www.youtube.com/watch?v=haUfb1ievTE&t=1489s)
Dan explains how the SSSF is designed to be an atomic, composable tool deployed across any codebase. A skill allows an agent to operate the factory, and a `/install` command copies the factory into a new repo. The skill includes a "cookbook" of lazy-loaded actions (set up factory, create ADW, modify config, etc.) that the agent can reference. He reiterates that the system is meant to be customized after installation.

### Vibe Coding vs. Agentic Engineering [26:54](https://www.youtube.com/watch?v=haUfb1ievTE&t=1614s)
Dan concludes by encouraging engineers to build their own software factories, push 80% junk work to agent stacks, and focus on net-new hard work. He defines the difference: vibe coding is not knowing how your system works and not looking; agentic engineering is knowing how it works so well you don't have to look. He points to his course, Tactical Agentic Coding, and notes the SSSF is free and open-source.
