# /wayfinder: Planning is no longer the AI bottleneck

[![/wayfinder: Planning is no longer the AI bottleneck](https://i.ytimg.com/vi/F3lL98Pj90o/hqdefault.jpg)](https://www.youtube.com/watch?v=F3lL98Pj90o)

## TL;DR
Wayfinder is an AI agent skill that orchestrates large-scale planning work across multiple sessions by creating a "map" of decision tickets in your issue tracker. It handles research, prototyping, grilling, and tasks—resolving the "fog of war" incrementally so you can tackle projects far too big for a single context window.

## Key Takeaways
- Wayfinder decouples planning from a single AI session, letting you map out enormous chunks of work that span multiple sessions and ticket types.
- The system models work as a journey from a vague start point to a destination, clearing a "fog of war" as decisions are resolved.
- It tracks a "frontier" of currently-decidable tickets alongside things still in fog, updating the map as each ticket is completed.
- Four ticket types exist: research, prototype, grilling (discussion), and tasks—each handled in its own session.
- Wayfinder stores its maps and sub-tickets directly in your issue tracker (GitHub, Linear, Jira, etc.) and is issue-tracker agnostic.
- Prototypes prevent the approach from becoming waterfall by providing high-fidelity feedback during planning.
- Once the map is complete, it can be converted into a spec and then into implementation tickets; specs are treated as non-persistent and can be discarded once the code exists.
- Wayfinder is best used when the path to your destination is genuinely foggy; if a single session suffices, use simpler tools instead.
- It works with any coding agent and has been applied beyond coding—e.g., planning a garden office.

## Detailed Breakdown

### The Problem with Single-Session Planning [00:00](https://www.youtube.com/watch?v=F3lL98Pj90o&t=0s)
Matt Pocock explains that existing planning tools, including his own "grill me" / "grill with doc" skills, are tied to a single AI session. This forces you to artificially shrink work to fit within an agent's context window and "smart zone." You end up pre-chunking work, only to hit unanswerable questions or get lost mid-session, all while managing token usage. He wanted an approach that lets you be genuinely ambitious without constraining the work to fit AI limitations.

### Introducing Wayfinder [01:04](https://www.youtube.com/watch?v=F3lL98Pj90o&t=64s)
Wayfinder is a skill available on Matt's skills repo that orchestrates planning across multiple session types. It understands that you can't go cleanly from start to destination—you have to clear the fog of war. It handles dependent decisions, supports parallel planning, and is grounded in software fundamentals Matt learned as a developer before AI. Users have already reported success: one user "oneshot a prototype" after months of restarts, and another built their own harness inspired by Wayfinder's star-map UI.

### How Big Work Gets Planned [02:04](https://www.youtube.com/watch?v=F3lL98Pj90o&t=124s)
Big work starts with a vague idea and a foggy path to a destination. The first step is typically a grilling session where the AI interviews you about the basic premise. For small work, that's enough. For larger work, you need additional sessions—prototyping, more grilling, research—each represented as a ticket on a conceptual map. Wayfinder creates and manages this map, tracking both the "frontier" (decisions you can make now) and everything still in fog.

### How Wayfinder Tracks Work [04:10](https://www.youtube.com/watch?v=F3lL98Pj90o&t=250s)
Wayfinder stores its maps and decision tickets in your issue tracker. In Matt's GitHub repo, each Wayfinder map is a parent issue with sub-issues for each decision ticket. As decisions are resolved, the resolution is written back into the parent map. The skill is issue-tracker agnostic—you can configure it for Linear, Jira, or anything else via a "setup map skills" step.

### Starting a Wayfinder Session [05:41](https://www.youtube.com/watch?v=F3lL98Pj90o&t=341s)
To kick off a session, you invoke the Wayfinder skill with a description of your destination. Matt's example: adding a command palette with icon picker, diagram search, and copy functionality to his CVM diagram app. Wayfinder explores the repo, invokes the grilling skill to interview you, asks what "done" looks like (recommending a spec), then creates an initial map with sub-issue tickets. In his example, seven tickets were created immediately, but only three were "takable" right now.

### Working Through the Map [06:44](https://www.youtube.com/watch?v=F3lL98Pj90o&t=404s)
Each ticket is worked through in its own session by calling Wayfinder with the ticket name/URL. Matt uses a "handoff skill" that auto-generates a prompt and spawns a Claude sub-agent, but the core action is simply calling Wayfinder on the specific ticket. You use Wayfinder both to chart the initial map and to walk through each ticket. As tickets are resolved, the frontier shifts and new tickets become available.

### The Four Ticket Types [07:46](https://www.youtube.com/watch?v=F3lL98Pj90o&t=466s)
1. **Research** — the agent goes off, finds information, and reports back, usually autonomously in a sub-agent.
2. **Prototype** — creates a prototype to bring ideas to life; this is what prevents the process from becoming waterfall.
3. **Grilling** — a discussion session about an implementation detail or plan aspect.
4. **Tasks** — real-world actions the agent can't do, or scheduled work behind other decisions.

### Blocking Relationships and the Frontier [09:18](https://www.youtube.com/watch?v=F3lL98Pj90o&t=558s)
Wayfinder establishes blocking relationships between tickets because some decisions depend on others being made first. As you work through the map, resolving a ticket opens up new tickets—the frontier moves. Matt shows a map with 14 of 17 tickets done, noting that even then, building the core skill may require revisiting other decisions based on how it turns out.

### From Map to Spec to Tickets [09:49](https://www.youtube.com/watch?v=F3lL98Pj90o&t=589s)
Once the map is complete, Matt converts it into a spec (using a "to spec" call on the Wayfinder map). The resulting spec is extremely dense and links back to the original decision tickets, so the agent can consult primary sources if confused—an advantage over "grill with docs," where the spec was the only source of truth. The spec is then turned into implementation tickets via his usual "to spec" → "to tickets" workflow. The initial spec draft was so large it exceeded GitHub's character limit.

### FAQ: When Should I Use Wayfinder? [11:51](https://www.youtube.com/watch?v=F3lL98Pj90o&t=711s)
If the work is completable in a single session, don't use Wayfinder—just do it. Wayfinder is for foggy, multi-session work where you don't know the path. Matt has also used it for non-coding tasks like planning a garden office: commissioning a site survey, researching builders, figuring out contacts.

### FAQ: Is This Spec-Driven Development? [12:24](https://www.youtube.com/watch?v=F3lL98Pj90o&t=744s)
Matt frames a spec as simply a "destination document" for multi-session work—a way to know where you were heading when you reach the end. Unlike spec-driven development where the spec persists and is edited, Matt closes the issue containing the spec once the code is written. The spec is non-persistent; once it's present in the code, the spec is deleted and rarely referenced again.

### Closing Thoughts [14:27](https://www.youtube.com/watch?v=F3lL98Pj90o&t=867s)
Matt finds Wayfinder liberating—it lets him start foggy projects and handles the difficult decisions along the way. He's used it for courses, engineering, and a garden office. The destination is flexible: you can generate a spec for an AFK agent to implement, or have Wayfinder implement work directly.
