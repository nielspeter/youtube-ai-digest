# New Skills! v1.2 brings /wait-what, /writing-for-agents, and fixes /grill-me

[![New Skills! v1.2 brings /wait-what, /writing-for-agents, and fixes /grill-me](https://i.ytimg.com/vi/gaDdrDdczO4/hqdefault.jpg)](https://www.youtube.com/watch?v=gaDdrDdczO4)

## TL;DR
Matt Pocock announces version 1.2.0 of his popular AI engineering skills, adding new skills like `/wait-what` (to combat LLM verbosity), `/writing-for-agents` (for cleaner agent configuration), `wizard` (interactive bash provisioning scripts), and `two-questionnaire` (for stakeholder collaboration), while significantly upgrading `/grill-me` to use a graph-based, multi-question-per-turn approach. The release also brings official Claude Code plugin marketplace integration, Codex compatibility via OpenAI YAML sidecar files, and a new documentation site at aihero.dev/skills.

## Key Takeaways
- The skills repo has reached ~24K GitHub stars, making it one of the platform's most-starbed projects, and now has dedicated documentation at aihero.dev/skills.
- The skills are now installable directly from the Claude Code official plugin marketplace as a read-only bundle with automatic updates.
- OpenAI YAML sidecar files have been added to every skill, enabling proper Codex compatibility with `allow implicit invocation: false` for user-invoked skills.
- `/wait-what` is a new skill that forces the agent to use ASD STE 100 simplified technical English and ground itself in the project's ubiquitous language from `context.md` to counter Opus 5's verbosity.
- `/grill-me` has been overhauled from one-question-per-turn to a graph-based, rounds system that asks multiple questions per turn, dramatically speeding up sessions while respecting question dependencies.
- `/writing-for-agents` is a generalization of the former "writing great skills" skill, now usable for any agent-readable configuration including `agents.md` and `claude.md`, and is model-invocable.
- `wizard` generates deterministic interactive bash scripts that walk a human through manual infrastructure steps (e.g., AWS provisioning), keeping the human in control while making the process guided and efficient.
- `two-questionnaire` converts grilling session decisions into a shareable markdown document for collaboration with non-technical stakeholders (e.g., via Google Docs).
- Matt is launching a self-paced AI coding crash course, reflecting his view that AI coding practices have stabilized enough since roughly December to support a durable curriculum.

## Detailed Breakdown

### Documentation Site Launch [00:00](https://www.youtube.com/watch?v=gaDdrDdczO4&t=0s)
Matt opens by announcing version 1.2.0 of his engineering skills, noting the GitHub repo has climbed to approximately 24K stars and ranks as the 24th most-starred repo of all time on GitHub. To match the project's maturity, he and his team built a proper documentation site at aihero.dev/skills. The site organizes skills into logical groupings (e.g., the main flow: grill with docs → to spec → tickets implement → code review), provides a full reference panel for every skill, includes a FAQ sourced from Matt's personal wiki of commonly asked questions, and links to an AI coding dictionary he has been assembling.

### Claude Code Plugin Marketplace Integration [01:01](https://www.youtube.com/watch?v=gaDdrDdczO4&t=61s)
The skills are now part of the official Claude Code plugin marketplace. Users can open Claude Code, search for "Matt Pocock" or "Matt Pocock skills," and install directly. This delivers a read-only bundle with no extra setup steps, and any updates Matt makes are automatically pulled down to users.

### Codex Compatibility via OpenAI YAML Files [01:33](https://www.youtube.com/watch?v=gaDdrDdczO4&t=93s)
For Codex users, Matt has added OpenAI YAML files for every skill. This ensures out-of-the-box compatibility with UIs like Codex UI. Critically, the `allow implicit invocation: false` setting—which keeps user-invoked skills hidden from the agent's context window until explicitly called—now travels over to Codex. Matt notes he hadn't initially realized Codex didn't support this natively, and the sidecar files fix that gap.

### `/wait-what` Skill for Opus Verbosity [02:36](https://www.youtube.com/watch?v=gaDdrDdczO4&t=156s)
Matt expresses frustration with Opus—especially Opus 5—producing overly verbose, jargon-heavy output that is hard to read. He tried output styles and `agent.md` tweaks without success. The new `/wait-what` skill addresses this by instructing the agent to use ASD STE 100 simplified technical English (clear, declarative sentences) and to ground itself in the ubiquitous language defined in `context.md`. Matt emphasizes that the real cure for verbosity is telling the agent to use *your* project's language, not just "simple language." Users invoke `/wait-what` whenever the agent's output is incomprehensible.

### `/grill-me` Overhaul: Graph-Based Rounds [04:11](https://www.youtube.com/watch?v=gaDdrDdczO4&t=251s)
Matt's most popular skill, `/grill-me`, previously asked one question per turn. This created a painful failure mode: by the end of a session, remaining easy questions still consumed one full turn each, making the experience feel sluggish. The updated version asks multiple questions per turn in "rounds," modeled as a dependency graph. Critical questions that unlock further questions are asked first; once answered, the next round of dependent questions opens up. The UI uses emojis and labeled questions (Q1, Q2, etc.) with recommended answers, allowing users—especially those using dictation—to rapidly confirm or modify answers. Matt demonstrates rounds one and two, showing how the system continuously pushes the "frontier of questions" forward.

### `/writing-for-agents` Skill [06:15](https://www.youtube.com/watch?v=gaDdrDdczO4&t=375s)
Matt realized he was using his "writing great skills" skill for more than just skills—it was useful for any agent-readable configuration. The rebranded `/writing-for-agents` skill can be used for `agents.md`, `claude.md`, or skill creation/editing. It includes extra skill mechanics in its reference file and is model-invocable, meaning the agent can pull it in automatically when modifying `agents.md`. Matt highlights its value for pulling bloated `agents.md` content into separate skills to reduce frontloading.

### `wizard` Skill for Interactive Provisioning [07:17](https://www.youtube.com/watch?v=gaDdrDdczO4&t=437s)
The `wizard` skill generates interactive bash scripts that guide a human through manual steps only they can perform—typically infrastructure provisioning (e.g., AWS setup). Matt emphasizes this is a deterministic script, not an agent-driven process, so no data is sent to Anthropic or any LLM. The wizard opens the exact pages needed, prompts for inputs like API keys, saves them to the correct files or GitHub secrets, and walks through stages with a clean UI. Matt describes the experience as transforming provisioning from "incredibly painful to weirdly joyful."

### `two-questionnaire` Skill for Stakeholder Collaboration [08:50](https://www.youtube.com/watch?v=gaDdrDdczO4&t=530s)
Named "the most boring skill name," `two-questionnaire` extracts decisions from a grilling session into a markdown document that can be shared with non-technical stakeholders. Matt describes using it during a "wayfinder" session to design a garden office: the agent generated questions, he put them in a Google Doc, and he and his wife walked through it together before feeding answers back to the agent. Matt acknowledges this is effectively a patch for the fact that agents are hard to collaborate with directly, especially for teams that aren't AI-native or don't use Slack/Teams with agent integration. He hopes to eventually delete the skill once better collaborative agent workflows exist.

### Wrap-Up and AI Coding Crash Course [10:25](https://www.youtube.com/watch?v=gaDdrDdczO4&t=625s)
Matt points listeners to the full v1.2.0 changelog on GitHub for smaller items not covered in the video. He then announces an upcoming self-paced AI coding crash course, distinct from his previous cohort-based paid courses. He believes AI coding practices have largely stabilized since around December, giving him confidence to release a cheaper, year-round, self-paced course that should remain relevant as the field evolves. A waitlist link is available in the video description.
